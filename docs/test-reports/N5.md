## 4. Arabic System-Font Fallback Portability Review for Milestone N6 Debian Packaging

Per Owner Priority 5, we audited how Arabic text shaping and font fallback are implemented across all three GUI/rendering surfaces (`radivine-render`, `radivine-control`, and `radivine-viewer`) and what `packaging/debian/control` currently declares.

### 4.1 Architecture of Arabic Font Fallback Across Radivine

1. **Radial Wheel Renderer (`crates/radivine-render/src/cache.rs:320-334`):**
   - `GlyphCache` initializes its primary `cosmic-text` `FontSystem` strictly from the embedded `assets/fonts/Inter-Variable.ttf` bytes so that Latin typography and all `Branching` golden PNG checksums (`T-REN5`) remain 100% deterministic across machines.
   - Because `Inter-Variable.ttf` does not contain Arabic (`U+0600..U+06FF`, `U+0750..U+077F`, `U+08A0..U+08FF`, `U+FB50..U+FDFF`, `U+FE70..U+FEFF`) glyphs, `GlyphCache::contains_arabic_script` routes any label/caption containing Arabic codepoints to a secondary `arabic_font_system` (`FontSystem::new_with_fonts`), which loads:
     - `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`
     - `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf`
   - These two TrueType font files are provided on Debian, Ubuntu, and Linux Mint by the **`fonts-dejavu-core`** package.
2. **Control Center & File Preview Viewer (`apps/radivine-control/src/ui/theme.rs:118-138`, `apps/radivine-viewer/src/lib.rs`, verified by `apps/radivine-control/tests/arabic_font_fallback.rs`):**
   - Both `eframe` applications enable the `eframe` `"system_fonts"` feature (`egui_system_font_provider::SystemFontProvider` + `harfrust` OpenType shaping), keeping bundled `Inter` at index `0` of `FontFamily::Proportional` and using Fontconfig (`libfontconfig.so.1`) to discover installed Arabic fonts (`DejaVu Sans` / `Noto Sans Arabic`) with full contextual joining (`isol`, `init`, `medi`, `fina`) and mandatory Lam-Alef (`لا`) ligature shaping (`rlig`).

### 4.2 Gap Identified in `packaging/debian/control` & Mandatory N6 Packaging Action

- **Current `packaging/debian/control` (`lines 12-13`):**
  ```debcontrol
  Depends: libc6 (>= 2.34), libgcc-s1 (>= 3.0)
  Recommends: nemo, libx11-6, libegl1, libgl1, systemd
  ```
- **Portability Risk if Unchanged:** On a minimal Debian/Ubuntu/Mint installation where `fonts-dejavu-core` or `libfontconfig1` is not pre-installed, `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` would be missing (causing `radivine-render` Arabic labels to fall back to `Inter` tofu boxes) or Fontconfig lookup in `radivine-control`/`radivine-viewer` could fail to resolve a system Arabic font.
- **Mandatory N6 Action Recorded for `packaging/debian/control`:**
  During Milestone N6 (`v0.3.0` `.deb` packaging), update `packaging/debian/control` to:
  ```debcontrol
  Depends: libc6 (>= 2.34), libgcc-s1 (>= 3.0), fonts-dejavu-core, libfontconfig1
  Recommends: nemo, libx11-6, libegl1, libgl1, systemd, fonts-noto-core
  ```
  - Adding **`fonts-dejavu-core`** and **`libfontconfig1`** to `Depends` guarantees that `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` and `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf` exist on disk for `radivine-render` and that `egui_system_font_provider` can query Fontconfig for `DejaVu Sans` Arabic glyphs in `radivine-control` and `radivine-viewer`.
  - Adding **`fonts-noto-core`** (`Noto Sans Arabic`) to `Recommends` provides additional Arabic coverage where recommended packages are installed.
