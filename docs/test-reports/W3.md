The practice area uses the existing semantic Light/Dark/System colors and type, with its own finite SVG transitions. No runtime framework or dependency was added.

Visitors can explore Branching (default), Concentric Rings, or named fallback scenarios. Hover dwell and outward motion open submenus; directional stems/neutral bridges explain Branching travel. The shared-center rings expand outward. Results explain what the desktop would do, including asynchronous conversion and logging-only Custom examples. Controls: **Open wheel** or **Start Invoke practice**; pointer hover/click; hold the sample, move and freshly press Shift for simulated Drag + Shift; release over an eligible leaf. Second Shift, Cancel, Escape, outside/hub drop or reset safely end the session. The action list provides equivalent submenu/outcome selection without dragging. On the focused surface, arrows cycle, Enter/Space selects, digits activate and Backspace goes up. Tab/Shift+Tab retain normal page navigation. Touch uses full-size list buttons with the wheel as a visual reference.

## Architecture and fidelity

The [W3 contract](../website/W3-demo.md) records source symbols, exact parameters and browser differences. Six small modules separate sample menus, geometry, state, input, rendering and outcomes. The reducer's phases are idle → active (including navigation) → result/cancelled → reset. It owns submenu path, hover, press pairing, input source, geometry generation, exposure guards, deadlines and inspection state. Context/layout/environment changes create a clean session. DOM and keyboard adapters cannot maintain a second selection state.

A source manifest pins v0.3.0 / `1aa009a08bab66646898016f1ba953051eac46f3` and checks hashes of 15 relevant application/engine/action/test files during every build. Geometry uses application defaults: root 40/128, child 34/108, deep 26/84, child gap 20, dwell 110 ms, grace 180 ms, angular hysteresis 3.5°, band 0.65, slop 6 and hub-close 150 ms. Branching candidate rotations/shrinking, capped child spans, neutral bridge, corridor hull and tangent intent geometry follow the inspected implementation. Concentric uses 60-thick rings, 6-pixel gaps, fixed center, strict neutral boundaries, sibling grace and 2-pixel exposure guards.

The native reference script compiles a temporary harness against the **unchanged** `radivine-wheel` crate. Its six checked-in, timestamped traces cover both layouts, text/image keyboard paths, placement/spans, dwell boundaries, inward sibling behavior and commits. Browser-model tests compare native numeric geometry within 0.002 logical pixels and 0.00001 radians, plus exact paths/hover/commit outcomes. The emitter ran successfully and was reproduced with the committed script. This exercises pure Rust engine behavior, not native windows, a desktop file manager or real actions.

Representative sources/tests include `default_menu`, `to_wheel_config`, `root_segment_spans`, `child_segment_spans`, `place_child`, `ring_geometry`, Branching/concentric handlers, actions AC 4.1 / C3.1 / C3.2, Branching scenarios 01–09 and concentric NAV3/4/5/7/9/SAFE cases. See the contract and [source manifest](../../website/tests/fixtures/demo-source.json) for exact paths/names.

Intentional differences are visible or documented: a fixed 900×800 virtual desktop; website typography, numeric labels and animations; bounded default-menu fixtures; no arbitrary monitor/edge/custom-menu geometry; stricter rejection of Branching's painted separator gaps; illustrative inspection timing; HTML list/touch access; scoped shortcuts and normal Tab behavior; synthetic drag cancellation rather than an OS drag protocol. Concentric sectors stay top-centered at each level, as the actual Rust implementation does—the plan's older parent-alignment wording was corrected. Properties assumes a supported file-manager handler.

## Accessibility and performance limits

The SVG duplicates the semantic action list and is hidden from accessibility APIs. Native labels, fieldsets, buttons, disabled reasons and polite status regions carry meaning. Keyboard selection announcements are separate from pointer-frame updates. No global key handler captures page navigation. Reset/cancel preserve a useful focus destination; submenu list replacement restores focus within the new list. Reduced motion removes transforms/transitions while preserving interaction deadlines. Small screens use the list instead of requiring tiny sector hits.

Automated accessibility checks and keyboard/touch emulation do **not** replace NVDA/VoiceOver, physical touch devices, Safari or manual high-zoom reading. Those reviews remain required before claiming full accessibility acceptance.

[Recorded measurements](media/W3/measurements.json) are local Chromium observations, not field LCP/INP, Lighthouse results or native application benchmarks. The lazy controller/model/data bundle is 24,627 bytes raw / 8,930 bytes gzip (8.72 KiB), below the 60 KiB demo target. The initial loader is 1,037 bytes gzip; existing inline executable scripts total approximately 1,456 bytes gzip, below the 20 KiB initial-JS target together. Initial measured resource transfer is approximately 124 KB, excluding the HTML navigation response. No external requests, browser errors or horizontal overflow occurred in the captures.

The final captures recorded CLS 0.00162 on desktop and 0.09444 on mobile (below the 0.1 target in these runs). A 200-event root-wheel sample under 4× CPU throttling measured 4.8 ms median, 6.4 ms p95 and 16.8 ms maximum synchronous dispatch cost. This measures JS/DOM cost and excludes paint, so it is not INP. A recording attempt ended when its browser process closed; a complete sequential rerun produced all final captures and measurements. No permanent animation loop runs. The controller keeps one earliest-deadline timeout, cancels inactive sessions, and reuses SVG groups on hover. No field-performance or real-desktop-parity claim follows from these measurements.
