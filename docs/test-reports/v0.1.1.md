## 4. Login Autostart Rendering Regression — Root Cause & Verification (`ADR-026`)

### 4.1 Forensic Root Cause Analysis (`journalctl --user -u radivine.service`)

During real Linux Mint 22.3 Cinnamon logout/login testing (`2026-10-23 21:48:10`–`21:48:53`):
1. **Logout / LightDM Greeter Handover (`21:48:10`–`21:48:15`):** When the user logged out of `:0`, `systemd --user` remained active while LightDM took ownership of `:0`. `radivine.service` (`Restart=on-failure`, `RestartSec=2`) restarted 3 times against `:0` with `Invalid MIT-MAGIC-COOKIE-1 key` until the new user login session began.
2. **Early Login Startup Before Muffin Compositor (`21:48:17.334` vs `21:48:18`):** At `21:48:17.334`, `/etc/X11/Xsession.d/95dbus_update-activation-env` imported `DISPLAY=:0` and `XAUTHORITY` into `systemd --user`. `radivine[1810086]` connected to X11 as the first client (`overlay_window="0x00200001"`), **~700 ms before `cinnamon --replace` (Muffin, PID 1810351) started at `21:48:18`** and ~140–870 ms before `csd-xsettings` / `csd-xrandr` finished applying DPI, theme, and monitor settings (`21:48:17.475`–`21:48:18.208`).
3. **Permanent Caching of `compositor_active = false` (`translucent = false`):**
   - `X11Platform::connect()` called `probe_with_connection()` only once at `21:48:17.334`. Because Muffin did not yet own `_NET_WM_CM_S0`, `self.doctor.compositor_active` was permanently cached as `false` (`Support::Degraded("no compositor owns _NET_WM_CM_S0; using opaque card fallback")`).
   - When the user summoned the radial wheel at `21:48:25` and `21:48:33` (after Muffin was already running), `prepare_overlay()` still returned `translucent: false`, activating `Renderer::set_opaque_fallback(true)` (which fills rectangular damage boxes with solid opaque `ring_fill` instead of `[0, 0, 0, 0]` transparent pixels and disables soft drop shadows) **and** applying an XShape `ShapeBounding` clip derived from `ws.input_region()` (which included invisible pointer hit-slop corridors such as `anchor_corridor_polygon` and child submenu hit corridors, rendering them as solid opaque dark wedges, and was not updated on `WheelEvent::HoverChanged`, clipping captions and hover expansions).
4. **Why Clicking "Restart Daemon" Fixed It (`21:48:53`):**
   - When the user clicked **Restart Daemon** in the Control Center at `21:48:53.923`, Muffin already owned `_NET_WM_CM_S0`. The restarted daemon (`radivine[1812728]`) probed `compositor_active = true` (`translucent = true`) at startup, disabling `opaque_fallback` and leaving `ShapeBounding` unclipped.

### 4.2 Implemented Fixes

1. **Dynamic Runtime Compositor & Display Tracking (`crates/radivine-platform/src/x11/mod.rs`, `doctor.rs`, `overlay.rs`):**
   - Subscribed `overlay.helper_window` to `XfixesSelectionNotify` on both `_NET_WM_CM_S0` and `_XSETTINGS_S0` (plus `PROPERTY_CHANGE` on the `_XSETTINGS_S0` owner window).
   - Added `X11Platform::refresh_compositor_state()` and `X11Platform::refresh_display_settings()`, invoked on XFixes/RandR/PropertyNotify events, inside `prepare_overlay()` before every wheel summon, and inside `sync_graphical_state()` on status queries.
   - When `_NET_WM_CM_S0` transitions to active, `X11Platform` immediately calls `reset_bounding_region`, re-asserts `_NET_WM_BYPASS_COMPOSITOR = 2`, clears the X11 window area to transparent (`0x00000000`) on map, and sets `OverlayInfo::translucent = true`.
   - Added a bounded startup wait (`wait_for_initial_compositor`, up to `2500 ms` default) when launched by `systemd --user` (`RADIVINE_SYSTEMD_SERVICE=1` or parent `comm == "systemd"`) and `_NET_WM_CM_S0` is initially unowned.
2. **Session & `ShapeBounding` Consistency (`apps/radivine/src/session.rs`):**
   - Explicitly clears any prior `ShapeBounding` clip (`set_bounding_region(None)`) whenever `translucent == true`.
   - In genuine uncomposited environments (`!translucent`), computes `ShapeBounding` strictly from visible `scene.wheels` disks and `scene.caption` (excluding invisible pointer hit-slop corridors) and updates `ShapeBounding` on `HoverChanged`, `SubmenuOpened`, and `SubmenuClosed`.
3. **Systemd Service Hardening & Graphical Readiness Telemetry (`packaging/radivine.service`, `apps/radivine-control`):**
   - Updated `radivine.service` with `After=default.target graphical-session-pre.target dbus.socket`, `StartLimitIntervalSec=0`, and `Environment=RADIVINE_SYSTEMD_SERVICE=1`, plus login X11 connection retry (`connect_platform_with_login_retry`).
   - Added backward-compatible `graphical_ready`, `compositor_active`, `translucent_overlay`, and `monitor_count` fields to `DaemonStatus` and surfaced them in the Control Center Dashboard and Diagnostics pages.
