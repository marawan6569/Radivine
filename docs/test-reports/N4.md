## 1. Configuration and Action Snapshot Implementation

### 1.1 `ActiveSessionSettings` (`apps/radivine/src/session.rs`)
Per `ARCHITECTURE.md` §A6–§A7, an immutable per-session snapshot (`ActiveSessionSettings`) is captured at the start of every wheel activation (`summon_invoke()` and `summon_drag()`) and cleared in `clear_active_session_snapshots()` only when the session returns to `Idle` or `Armed`:

- `config: AppConfig` — Full application configuration snapshot (`wheel`, `appearance`, `input`, `convert`, `jobs`).
- `wheel_cfg: WheelConfig` — Effective `WheelConfig` locked for the session (`root 40/128`, `child 34/108`, `child_offset_gap 20`, `hover_dwell_ms 110`, `submenu_grace_ms 180`, `leave_grace_ms 350`, `angular_hysteresis_deg 3.5`, `max_depth 4`).
- `requested_layout: WheelLayout` — Layout requested by `config.wheel.layout` (`Branching` or `Concentric`).
- `effective_layout: WheelLayout` — Runtime layout selected before mapping after compositor and full-depth viewport fit validation (`Rreserve = 326 lp`).
- `fallback_reason: Option<LayoutFallback>` — Recorded fallback reason (`NoCompositor`, `InsufficientSpace`, or `TargetTooSmall`) if `requested_layout == Concentric` fell back to `Branching`.
- `scale: f32` — Active monitor scale factor locked for the duration of the session.
- `monitor_rect: (i32, i32, u32, u32)` — Active monitor physical origin and dimensions locked at activation (`ARCHITECTURE.md` §A7).
- `theme: Theme` — Resolved theme (`Dark` or `Light`) locked for the session.
- `reduced_motion: bool` — Resolved reduced-motion flag locked for the session.
- `passthrough: bool` — Input pass-through policy locked for the session (`false` by default in Drag mode per `ADR-0001`).
- `registry: Arc<ActionRegistry>` — Action registry and menu tree snapshot (`Arc::clone(&self.registry)`) captured at activation.
- `menu_limits: MenuLimits` — Ring capacity and depth limits (`max_root_items = 8`, `max_child_items = 8`, `max_depth = 4`).
- `action_index: HashMap<ItemPath, ActionId>` — Menu path to `ActionId` mapping captured when the session menu is built and updated only when session-scoped enrichment rebuilds the menu against the session's `registry`.

### 1.2 Audit of Active-Session Reads (`apps/radivine/src/session.rs`)
All runtime reads during an active wheel session (`Summoning`, `Active`, `LeftGrace`, `Committing`, `Dismissing`, or while `pending_drop_selection.is_some()`) route through `self.active_settings` rather than mutable daemon-wide `self.config` or `self.registry`:

- **IPC `Reload` (`reload_config`):** Updates `self.config`, `self.registry`, and `self.last_reload_status` for *future* activations only. While a wheel session is active, `reload_config()` does **not** mutate `self.wheel_cfg`, `self.effective_scale`, or the renderer's active theme, and never hides, remaps, or recreates the active overlay window.
- **Session-End Graphical Synchronization (`clear_active_session_snapshots`):** When a session finishes (`Idle` or `Armed`), `SessionController` clears `active_settings` and `pending_drop_selection`, calls `self.platform.sync_graphical_state()`, and refreshes `self.wheel_cfg`, `self.renderer.set_theme(...)`, and `self.effective_scale` so any deferred scale/config/theme changes take effect cleanly before the next activation (`ARCHITECTURE.md` §A7).
- **Enrichment Updates (`poll_enricher`):** Evaluates `session_registry` against `self.current_ctx`, refreshes `active_settings.action_index`, and updates item enabled states via `ws.set_enabled_at(&id, enabled, now_ms)` using the current session elapsed timestamp so newly enabled Concentric submenus start dwell timing from `now_ms`.
- **Action Identity Pinning (`PendingDropSelection`):** When `DndDrop` commits on a leaf or default-child submenu while URI payload resolution is still pending (`Summoning`), `SessionController` captures `PendingDropSelection { path, action_id: ActionId }` using the `ActionId` pinned in `active_settings.action_index` at drop time. If `action_index.get(&path)` is `None`, the drop is rejected immediately (`dnd_finish(false)`).
- **Synchronous Pre-Commit Eligibility Check (`can_commit_action`):** Immediately before `platform.dnd_finish(true)` and `dispatch_action_by_id()` (both on immediate drop and when deferred URI payload resolution completes), `SessionController::can_commit_action(&action_id, &ctx, InvocationMode::Drag)` verifies synchronously against the session's `registry` and resolved `BasicContext` that the captured `ActionId` still exists, matches `modes`, passes `visibility` (`! hidden_when`), and passes `enabled_when`. If ineligible, `dnd_finish(false)` is sent and no substitute action at the same `ItemPath` is ever executed.
- **Conversion Presets & Active Jobs Isolation:** `dispatch_action_by_id` reads `convert` presets from `self.session_app_config()`, preserving running conversion job configurations across reloads.

## 2. X11 Integration and Runtime Fallback Behavior

### 2.1 Pre-Activation Selection and Full Configured-Depth Reservation (`PRODUCT_SPEC.md` §P3, `INTERACTION_DESIGN.md` §I2)
1. **No-Compositor Pre-Activation Check (`LayoutFallback::NoCompositor`):** In `summon_invoke()` and `summon_drag()`, after `platform.prepare_overlay(at)` and before `WheelSession::new` or `platform.map_overlay()`, if `wheel_cfg.layout == WheelLayout::Concentric && !info.translucent`, `SessionController` overrides `effective_wheel_cfg.layout = WheelLayout::Branching` and records `ws.record_layout_fallback(LayoutFallback::NoCompositor)`.
2. **Full Configured-Depth Reservation (`Rreserve = 326 lp`, No Dynamic Depth Reduction):** When compositor translucency is active, `WheelSession::new` evaluates `ConcentricActivationPlan::compute(&cfg, screen, anchor)` (`crates/radivine-wheel/src/concentric.rs:280-299`). `reserved_outer_radius` always reserves the full configured `max_depth = 4` rings (`root 40..128 lp` + three child rings of `60 lp` radial thickness and `6 lp` radial gap = `Rreserve = 326 lp`) with an `8 lp` minimum viewport edge pad (`min_dimension = 2 * (326 + 8) = 668 lp`). Radivine never reduces `max_depth` dynamically to force Concentric onto a smaller viewport.
3. **Target Geometry Validation (`TargetTooSmall`):** `ConcentricActivationPlan::compute` validates every ring and submenu in the menu tree against the `32×32 lp` target core (`MIN_TARGET_THICKNESS = 32.0`, `MIN_TARGET_ARC_CHORD = 32.0`). If the viewport is smaller than `668×668 lp` (`InsufficientSpace`) or any ring fails target geometry (`TargetTooSmall`), `WheelSession` falls back to `WheelLayout::Branching` before the overlay is mapped and displays `"Using Branching: nested rings need more space"` in the center hub when no item is hovered.

### 2.2 Single Overlay Window & `ShapeInput` Policy (`ARCHITECTURE.md` §A7, `T-X112`)
- Both `Branching` and `Concentric` use the single per-monitor X11 overlay window (`crates/radivine-platform/src/x11/mod.rs`). No separate platform windows are ever created for child rings.
- **Invoke Mode & Default Drag Mode (`input.passthrough == false`, `ADR-0001`):** With a compositor (`translucent == true`), `SessionController::sync_input_region` (`apps/radivine/src/session.rs:2365-2376`) sets `platform.set_input_region(None)` (full-overlay input capture). Releasing outside the wheel, inside the central hub, on a separator, in a radial gap, or in the outer safety margin is captured by the overlay and rejected cleanly (`XdndFinished(accepted=false, action=None)` in Drag mode; dismiss in Invoke mode), never falling through to an underlying file manager window.
- **Explicit Drag Pass-Through Mode (`input.passthrough == true` in Drag mode):** `WheelSession::rebuild_input_region_concentric` (`crates/radivine-wheel/src/session.rs:3397-3419`) emits strictly:
  1. The solid reserved disc `Shape::Circle { c: center, r: Rreserve + hit_margin }` (`326 + 12 = 338 lp` in app config; `326 + 16 = 342 lp` in engine defaults) with zero annular holes;
  2. When `center` is displaced from `anchor` by `> 2.0 lp`, the anchor disc `Shape::Circle { c: anchor, r: 24.0 }` and the convex approach corridor polygon connecting `anchor` to the reserved disc.
  - The `280×64 lp` bottom caption box is **never** added to `input_region`, remaining non-interactive and excluded from pass-through `ShapeInput`.
  - Because the reserved disc is fixed at `Rreserve + hit_margin` for the entire session, `ShapeInput` never shrinks or develops holes as child rings open, switch, or retract.

### 2.3 Display, Monitor, Scale, and Compositor Guards (`ARCHITECTURE.md` §A7, `T-SAFE8`)
- **Compositor Loss or Monitor Geometry Change (`MonitorsChanged` or `SettingsChanged` where `!compositor_active` or active monitor disappeared/resized):**
  - Calls `handle_concentric_display_invalidation(now)`.
  - In **Invoke** mode: dismisses immediately (`dismiss_immediate()`) with zero action execution.
  - In **Drag** mode: latches `self.reject_until_drag_end = true`, clears `pending_drop_selection`, transitions `Summoning | LeftGrace -> Active` so the capture overlay **remains mapped**, calls `ws.suspend_interaction(ms)`, replies `platform.dnd_reply(false)`, and prevents `MAX_SESSION_DURATION` or in-flight `Payload` errors from hiding the overlay until `DndDrop` (rejected with `dnd_finish(false)`), `DndLeave`, or `DragDisarmed` ends the source drag.
- **Scale / Theme / Config Change (`SettingsChanged` while compositor and active monitor geometry are unchanged):**
  - Deferred while a wheel session is active; synchronized cleanly in `clear_active_session_snapshots()` once the session returns to `Idle` or `Armed`.

## 3. Control Center Layout Selector and Persistence

### 3.1 Wheel Layout Card (`apps/radivine-control/src/ui/mod.rs`)
Per `PRODUCT_SPEC.md` §P4, the **Wheel** page in `radivine-control` renders the **Wheel Layout** card first:

- **Branching (Default)** (`"branching"`): *"Submenus open beside their parent, connected by vine stems."*
- **Concentric Rings** (`"concentric"`): *"Submenus open as rings around one center. Uses Branching when the rings cannot fit on this display."*
- Shared help text: *"Applies to the next wheel activation. An open wheel stays as it is."*
- Runtime status line (`wheel_layout_status_message`): distinguishes saved preference from effective runtime layout and reports `insufficient_space`, `target_too_small`, `no_compositor`, and active-session queued layout changes accurately.
- **Root Geometry vs. Branching Geometry:**
  - `root_inner_radius` (`40.0`) and `root_outer_radius` (`128.0`) remain editable for both layouts.
  - Displays read-only informational text: *"Nested ring thickness: 60 px; gap: 6 px"*.
  - `child_inner_radius` (`34.0`), `child_outer_radius` (`108.0`), and `child_offset_gap` (`20.0`) are grouped under **Branching geometry** and disabled contextually (`add_enabled_ui(is_branching, ...)`) when **Concentric Rings** is selected in the draft, while preserving their stored numeric values in `AppConfig` and `config.toml`.
- **Restore Wheel Defaults (`restore_wheel_defaults`):** Resets `draft_config.wheel` to `AppConfig::default().wheel` (`layout = WheelLayout::Branching`, `root_inner_radius = 40.0`, `root_outer_radius = 128.0`, `child_inner_radius = 34.0`, `child_outer_radius = 108.0`, `child_offset_gap = 20.0`, `hover_dwell_ms = 110`, `submenu_grace_ms = 180`, `leave_grace_ms = 350`, `angular_hysteresis_deg = 3.5`).

### 3.2 Atomic Document-Preserving Persistence (`apps/radivine-control/src/persistence.rs`)
- `DEFAULT_CONFIG_TOML_TEMPLATE` and `packaging/config.example.toml` include `layout = "branching"` under `[wheel]`.
- `apply_app_config_to_toml_doc` writes canonical lowercase `"branching"` or `"concentric"` to `doc["wheel"]["layout"]` via `toml_edit::DocumentMut`, preserving user comments, unknown keys, `[input]`, `[appearance]`, `[convert]`, and `[jobs]` settings, and writing via `.config.toml.tmp` + `fsync` + `.bak` backup + atomic `rename`.
- Saving layout changes never touches or rewrites `actions.toml` or `convert.toml`.
