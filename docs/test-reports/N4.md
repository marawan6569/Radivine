## 1. Configuration and Action Snapshot Implementation

### 1.1 `ActiveSessionSettings` (`apps/radivine/src/session.rs`)
Per `ARCHITECTURE.md` §A6, an immutable per-session snapshot (`ActiveSessionSettings`) is captured at the start of every wheel activation (`summon()` and `drag_enter_with_cursor_and_timestamp()`) and cleared when `deactivate()` completes (`wheel.phase() == SessionPhase::Idle`):

- `config: Arc<AppConfig>` — Full application configuration snapshot (`wheel`, `appearance`, `input`, `convert`, `jobs`).
- `requested_layout: WheelLayout` — Layout requested by `config.wheel.layout` (`Branching` or `Concentric`).
- `effective_layout: WheelLayout` — Runtime layout selected after pre-activation compositor and viewport fit validation.
- `layout_fallback: Option<LayoutFallback>` — Recorded fallback reason (`NoCompositor`, `InsufficientSpace`, or `TargetTooSmall`) if `requested_layout == Concentric` downgraded to `Branching`.
- `scale_factor: f32` — Active monitor scale factor locked for the duration of the session.
- `theme: ThemeConfig` — Resolved theme colors and reduced-motion flag (`appearance.reduced_motion`) locked for the session.
- `passthrough_enabled: bool` — Input passthrough policy locked for the session (`false` in Drag mode per `ADR-0001`).
- `registry: Arc<ActionRegistry>` — Action registry and menu tree snapshot (`Arc::clone(&self.registry)`) captured at activation.
- `menu_limits: MenuLimits` — Ring capacity and depth limits (`max_root_items`, `max_child_items`, `max_depth`) derived from the session config.

### 1.2 Audit of Active-Session Reads (`apps/radivine/src/session.rs`)
All runtime reads during an active wheel session (`Summoning`, `Active`, `LeftGrace`, `Committing`, `Dismissing`, or while `pending_drop_selection.is_some()`) were audited and routed through `self.active_session` rather than mutable daemon-wide `self.config` or `self.registry`:

- **IPC `ReloadConfig` (`handle_ipc_command`):** Updates `self.config` and `self.registry` for *future* activations only. When `is_wheel_active()` is true, `reload_config()` does **not** call `apply_config_to_wheel_and_theme`, does **not** hide/remap/recreate the overlay window, and marks `layout_pending = (active.requested_layout != self.config.wheel.layout)` in `DaemonStatus`.
- **Enrichment Updates (`process_enrichment`):** Evaluates `session_registry.evaluate(&self.context)` against the session's captured `Arc<ActionRegistry>` and updates item enabled states via `self.wheel.set_enabled_at(&id, enabled, now_ms)` using the current session elapsed timestamp so newly enabled submenus in Concentric mode reset their dwell baseline to `now_ms` instead of `0`.
- **Action Identity Pinning (`PendingDropSelection`):** When `WheelSession::drag_drop` returns `SessionOutcome::Committed(selection)` while URI payload resolution is still pending, `SessionController` stores `PendingDropSelection { action_id: selection.action_id, menu_path: selection.menu_path, mode: selection.mode }` rather than a raw `MenuPath`.
- **Synchronous Pre-Commit Eligibility Check (`can_commit_action`):** Immediately before `platform.accept_drop()` and `execute_committed_action()` (both on immediate drop and when deferred URI payload resolution completes), `SessionController::can_commit_action(&selection.action_id)` verifies synchronously against `active_session.registry` and `self.context` that the captured `ActionId` still exists, is visible, and is enabled for the resolved `SelectionContext`. If the action is absent, invisible, disabled, or invalid, the drop is rejected via `platform.reject_drop()` with zero side effects and never falls back to whatever action currently occupies `selection.menu_path`.
- **Conversion Presets & Active Jobs Isolation:** `execute_committed_action` reads `convert` presets and `jobs` limits from `active_session.config` (falling back to `self.config` only if no session is active), preserving running conversion job snapshots across reloads.

## 2. X11 Integration and Runtime Fallback Behavior

### 2.1 Removal of Temporary N2 Clamp and Pre-Activation Selection
The temporary N2 desktop clamp that forced `WheelLayout::Branching` in `apps/radivine/src/session.rs` was removed after integrating all N4 runtime safeguards:

1. **Compositor Check (`LayoutFallback::NoCompositor`):** Before mapping the overlay window, if `requested_layout == WheelLayout::Concentric` and `!self.platform.compositor_Status().supports_translucency()`, `SessionController` calls `self.wheel.record_layout_fallback(LayoutFallback::NoCompositor)` and activates `WheelLayout::Branching` with opaque fallback styling.
2. **Viewport Fit & Target Size Check (`InsufficientSpace` / `TargetTooSmall`):** When compositor translucency is available, `WheelSession` evaluates `ConcentricActivationPlan::compute` against the monitor's logical `ScreenRect` (`12.0 px` minimum outer margin, `24.0 px` minimum inner arc length, `16.0 px` minimum radial thickness). If even a single ring (`active_max_depth = 0`) cannot fit or would produce undersized targets, `WheelSession` automatically falls back to `WheelLayout::Branching` before the window is mapped.
3. **Fallback Caption (`crates/radivine-wheel/src/session.rs`):** When `WheelSession` falls back to `Branching` due to `InsufficientSpace` or `TargetTooSmall`, `rebuild_scene_branching` displays `"Using Branching: nested rings need more space"` in the center hub when no segment is hovered (`hovered_item.is_none()`), using a pre-allocated `Arc<str>` on `WheelSession` (zero warm heap allocations).

### 2.2 Single Overlay Window & Solid Reserved-Disc `ShapeInput` (`T-X112`)
- Both `Branching` and `Concentric` use the single existing X11 overlay window and capture lifecycle (`crates/radivine-platform/src/lib.rs`). No separate platform windows are ever created for child rings.
- In `Concentric` Invoke mode (`passthrough_enabled == true`), `Scene::input_Passthrough_shapes` emits a single solid `HitShape::Circle` of radius `r_reserve + 12.0 px` centered at `effective_center`, plus the fixed `280x64` caption `HitShape::RoundedRect` when visible. This guarantees zero annular holes between rings and covers the entire displaced-center approach corridor (`T-SAFE7`) while rings open, switch, or retract.
- In Drag mode (`passthrough_enabled == false`, `ADR-0001`), the full-monitor capture window remains active throughout the drag session so releasing outside the wheel, inside the central hub, on a separator, in an inter-ring gap, or in the outer safety margin sends `XdndFinished(accepted=false, action=None)` and never leaks the drop to an underlying file manager window.

### 2.3 Display & Compositor Change Guards (`ARCHITECTURE.md` §A7)
- During an active `Concentric` session, `PlatformEvent::SettingsChanged` is inspected:
  - If compositor translucency was lost mid-session (`!compositor_status.supports_translucency()`), `handle_concentric_display_invalidation` immediately cancels the session cleanly without committing any action.
  - If the session is a Drag session, `self.reject_until_drag_end = true` is armed: the overlay hides (`set_visible(false)`), any active drop is rejected (`reject_drop()`), and all subsequent `DragMove` / `DragDrop` events for the remainder of the drag are rejected with `DragResponse { accepted: false, action: DragAction::None }` until `DragLeave` clears `reject_until_drag_end`.
  - Non-compositor `SettingsChanged` events (monitor geometry or scale changes) during an active `Concentric` session are deferred until `deactivate()` completes so the active wheel never jumps or switches layout mid-gesture.

## 3. Control Center Layout Selector and Persistence

### 3.1 Wheel Layout Card (`apps/radivine-control/src/ui/mod.rs`)
Per `PRODUCT_SPEC.md` §P4, the **Wheel** page in `radivine-control` renders the **Wheel Layout** card first:

- **Branching (Default)** (`"branching"`): *"Submenus open beside their parent, connected by vine stems."*
- **Concentric Rings** (`"concentric"`): *"Submenus open as rings around one center. Uses Branching when the rings cannot fit on this display."*
- Shared help text: *"Applies to the next wheel activation. An open wheel stays as it is."*
- Runtime status line (`wheel_layout_status_message`):
  - Distinguishes saved preference from effective runtime layout.
  - When `layout_pending` is true on `DaemonStatus`: displays that the saved preference is queued for the next wheel activation while the current session remains unchanged.
  - When `layout_fallback_reason` is `Some("insufficient_space" | "target_too_small")` or `Some("no_compositor")`: displays an accurate fallback explanation.
- **Root Geometry vs. Branching Geometry:**
  - `root_inner_radius` and `root_outer_radius` remain enabled for both layouts.
  - Displays read-only informational text: *"Nested ring thickness: 60 px; gap: 6 px"*.
  - `child_inner_radius`, `child_outer_radius`, and `wheel_gap` are grouped under **Branching geometry** and disabled contextually (`add_enabled_ui(is_branching, ...)`) when **Concentric Rings** is selected in the draft, while preserving their stored numeric values in `AppConfig` and `config.toml`.
- **Restore Wheel Defaults (`restore_wheel_defaults`):** Resets `draft_config.wheel` to `WheelConfig::default()` (`layout = WheelLayout::Branching`, `root_inner_radius = 52.0`, `root_outer_radius = 128.0`, `child_inner_radius = 38.0`, `child_outer_radius = 96.0`, `wheel_gap = 18.0`, `open_dwell_ms = 90`, `close_grace_ms = 120`, `cancel_grace_ms = 140`, `edge_margin = 16.0`).

### 3.2 Atomic Document-Preserving Persistence (`apps/radivine-control/src/persistence.rs`)
- `DEFAULT_CONFIG_TOML_TEMPLATE` and `packaging/config.example.toml` include `layout = "branching"` under `[wheel]`.
- `apply_app_config_to_toml_doc` writes canonical lowercase `"branching"` or `"concentric"` to `doc["wheel"]["layout"]` via `toml_edit::DocumentMut`, preserving user comments, unknown keys, `[input]`, `[appearance]`, `[convert]`, and `[jobs]` settings, and writing via `.config.toml.tmp` + `fsync` + `.bak` backup + atomic `rename`.
- Saving layout changes never touches or rewrites `actions.toml` or `convert.toml`.
- **Truthful Save / IPC Status Reporting:**
  - Daemon online & reload succeeds: `banner_ok = Some("Configuration saved and reloaded.")`, `banner_err = None`.
  - Daemon offline: `banner_ok = Some("Saved; applies when daemon starts.")`, `banner_err = None`.
  - Daemon online & IPC reload fails: file remains saved on disk, `banner_ok = None`, `banner_err = Some("Saved; daemon reload failed: ...")`.

### 7.3 Arabic Font Fallback Portability Risk & Missing-Font Verification
- **Current Mechanism:** The bundled UI font (`assets/fonts/Inter-Variable.ttf`) covers Latin, Greek, and Cyrillic scripts, but does not contain Arabic glyphs (`U+0600..U+06FF`).
  - In `crates/radivine-render/src/cache.rs:320-334` (`AssetCache::new`), `arabic_font_system` loads `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` and `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf` from the host filesystem when present.
  - In `apps/radivine-control` and `apps/radivine-viewer`, `egui` uses `egui_system_font_provider` to query host system fonts via `fontconfig` (`tests/arabic_font_fallback.rs`).
- **Graceful Fallback Verification:**
  - If the host DejaVu Sans files are absent (`ar_db.faces().count() <= 1`), `AssetCache::new` sets `arabic_font_system = None` without error or panic, and `AssetCache::text_mask` (`crates/radivine-render/src/cache.rs:451-457`) seamlessly falls back to `self.font_system` (`Inter-Variable.ttf`), rendering non-crashing fallback glyphs within the fixed `280x64` caption box.
  - In `apps/radivine/tests/nested_acceptance.rs::scenario_11_12_branching_drag_parity_and_arabic_filename_rendering`, dragging a disposable Arabic-named file (`"تجرية_ملف.txt"`) through `SessionController` and `Renderer::render` rendered cleanly into the `640x640` buffer with zero panics and preserved the source file untouched.
- **Portability Risk for N5/N6:** On minimal Linux installations or container images that lack `fonts-dejavu-core` (or `fonts-noto-core`), `radivine-render` will fall back to `Inter-Variable.ttf` tofu boxes for Arabic text. This should be tracked in N5/N6 (either by ensuring `fonts-dejavu-core` is declared in `packaging/debian/control` `Recommends`/`Depends` or documenting the system font requirement in release notes).
