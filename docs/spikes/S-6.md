## 2. Empirical Findings

### 2.1 How GTK 3.24.41 Interprets `XdndActionPrivate`

In `gdkdnd-x11.c` (`xdnd_action_from_atom`, lines 398–414):
```c
if (xatom == gdk_x11_get_xatom_by_name_for_display (display, "XdndActionPrivate"))
  return GDK_ACTION_COPY;
```
GTK3 maps `XdndActionPrivate` to `GDK_ACTION_COPY` on its internal `GdkDragContext` (`GTK_CONTEXT_ACTION_CHANGED: action=['GDK_ACTION_COPY']`). Because `context->action` is `GDK_ACTION_COPY` (not `GDK_ACTION_MOVE`) and Radivine never requests the `DELETE` selection target, GTK3 **never** emits `drag-data-delete` on the source widget and finishes the drag immediately upon `XdndFinished(success=1, XdndActionPrivate)` with zero snap-back animation.
