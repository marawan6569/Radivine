# Spike S-4: X SHAPE `ShapeInput` Pass-Through, Dynamic Expansion & Capture-All Comparison

- **Status:** Executed & Verified (**PASS — Behavioral Trade-Off Documented**)
- **Date:** 2026-10-22
- **Environment:** Linux Mint 22.3 (Zena), Cinnamon 6.6.3 (Muffin), X.Org 1.21.1.11 (`DISPLAY=:1`), X SHAPE 1.1, GTK 3.24.41
- **Spike Binary:** [`spikes/xdnd-overlay/src/main.rs`](file:///home/marwanmohamed/Documents/work/rust/radivine/spikes/xdnd-overlay/src/main.rs)

## 1. Objective & Hypothesis

Verify **H-4**:
1. Does `gdkdnd-x11.c` (`gdk_window_cache_shape_get` / `window_is_shape_visible`) honor the X11 Nonrectangular Window Shape Extension's **input region** (`ShapeInput` = `SK::INPUT`) while keeping the visual bounding region (`ShapeBounding`) unclipped for smooth anti-aliased alpha edges and drop shadows?
2. Does dynamically updating `ShapeInput` mid-drag (e.g., when a child wheel opens adjacent to the parent wheel) immediately expand the XDND hit region without interrupting the active drag?
3. What are the exact behavioral differences and user-safety trade-offs between **Input-Shape Pass-Through (`passthrough = true`)** and **Full-Monitor Capture-All (`passthrough = false`)**?

## 2. Empirical Findings

### 2.1 `ShapeInput` Pass-Through (`--shape-mode disc`) Works and Re-Enters Cleanly

In `S-4a`, the `400×400` overlay was configured with a circular `ShapeInput` mask of radius `r = 150 px` centered at `(200, 200)` (root `(220, 220)`):
1. At `(280, 220)` (`r = 60 <= 150`), the pointer is inside the shaped disc and over the accept ring (`XDND_POSITION #2`, `reply_accept=true`).
2. When the pointer moves to `(470, 220)` (`r = 250 > 150`), even though `(470, 220)` is still inside or adjacent to the overlay, it is outside the `ShapeInput` mask:
   - GTK3 immediately sends `XDND_LEAVE` (`button_held=true, owner=0x7400011, drag_ended=false`) to the Radivine overlay (which remains mapped and visible!).
   - Simultaneously, GTK3 retargets the drag to the underlying folder window (`UNDERLYING_FOLDER_MOTION: pos=(115,92)`).
3. When the pointer moves back inside the disc to `(280, 220)`, GTK3 sends `UNDERLYING_FOLDER_LEAVE` to the underlying folder and a fresh `XDND_ENTER` + `XDND_POSITION #3` to the Radivine overlay, completing `XDND_DROP` (`DROP_PAYLOAD_OK` in `1,762 µs`).

### 2.2 Critical Behavioral Discovery: The `Shift`-Held Native `MOVE` Hazard Under Pass-Through (`S-4b`)

In `S-4b`, the user summons the wheel with `Shift`, moves the pointer outside the `r = 150` `ShapeInput` disc to `(470, 220)` over an underlying folder **while still holding `Shift`** (or simply expecting that releasing the mouse outside an open radial menu cancels the menu), and releases the mouse button:
- Because the pointer passed through to the underlying GTK3 folder window while `Shift` was held, GTK3 set `suggested_action=['GDK_ACTION_MOVE']` and `selected_action=['GDK_ACTION_MOVE']` on the underlying folder!
- Releasing the mouse button executed a **native `MOVE` into the underlying folder** (`UNDERLYING_FOLDER_DROP: selected_action=['GDK_ACTION_MOVE']`, `GTK_SOURCE_DATA_DELETE_CALLED`) while the Radivine wheel was still visibly rendered on screen!

> [!WARNING]
> **Acceptance Criteria Contradiction Resolved (`AC-3.7`, `AC-3.8`, `AC-3.12`):**
> `IMPLEMENTATION_PLAN.md` §5.2 `AC-3.7` / `AC-3.8` state that under `passthrough = true`, dragging outside the wheel into a Nemo folder should drop into that folder, whereas `AC-3.12` states that after all M0 tests, no test file in `/tmp/radivine-m0-test/` has changed location. If `Shift` is held when dropping onto a Nemo folder on the same filesystem, Nemo performs a **move** (`GDK_ACTION_MOVE`), changing the file's location! Therefore:
> 1. Any test of native folder pass-through drop (`AC-3.7`/`AC-3.8`) must either use our instrumented `gtk3_drag_harness.py` (which logs `UNDERLYING_FOLDER_DROP` without moving disk files) or use a dedicated disposable file outside the `checksums.before` set.
> 2. We must clearly document the behavioral trade-off between `passthrough = true` (Shaped Cluster) and `passthrough = false` (Capture-All) in `ADR-016` and `PLATFORM_INTEGRATION.md`.

### 2.3 Dynamic Mid-Drag `ShapeInput` Expansion for Child Wheels (`S-4c`)

In `S-4c` (`--shape-mode expand-child`), the `500×400` overlay started with a single parent `ShapeInput` disc at local `(140, 200)` (`r = 112`). After `120 ms` mid-drag, `set_disc_input_shape` updated `ShapeInput` via `shape_mask(SO::SET, SK::INPUT, ...)` to the union of:
- Parent disc `(140, 200, r = 112)`
- Corridor rectangle `(220, 155)..(280, 245)`
- Child disc `(320, 200, r = 85)`

When the pointer moved across the corridor to root `(450, 220)` (local `(370, 200)`, inside the child wheel ring), `gdkdnd-x11.c` immediately recognized the updated `ShapeInput` region without emitting any `XDND_LEAVE`, delivered `XDND_POSITION #3: root=(450,220), local=(370,200), reply_accept=true`, and completed `XDND_DROP` (`DROP_PAYLOAD_OK` in `1,144 µs`).

### 2.4 Capture-All Mode (`--shape-mode capture-all`, `S-4d`)

In `S-4d`, `reset_input_shape_to_full` left `ShapeInput` unshaped across the `700×500` overlay:
- Moving the pointer far outside the wheel ring to `(470, 220)` (directly over the underlying folder while holding `Shift`) remained on the Radivine overlay (`XDND_POSITION #2: root=(470,220), local=(600,250), reply_accept=false`).
- **Zero** motion or drop events reached the underlying folder.
- Releasing the mouse button outside the wheel safely **cancelled** the drag (`GTK_CONTEXT_CANCEL: reason=no-target`), matching standard radial/context menu UX ("releasing outside the menu cancels").
- When the user genuinely wants to resume a normal Nemo drag-and-drop after summoning Radivine, pressing `Shift` a second time (`TRIGGER_TOGGLE_OFF`, verified in `S-6c`) unmaps the overlay and returns the drag to Nemo.

### 2.5 Comparison Summary: Shaped Pass-Through vs. Capture-All

| Property | Shaped Cluster Pass-Through (`passthrough = true`) | Full-Monitor Capture-All (`passthrough = false`) |
|---|---|---|
| **Behavior outside wheel cluster (`r > hit_radius`)** | Pointer passes through to Nemo/desktop underneath (`XDND_LEAVE` with `drag_ended=false`; wheel stays visible). | Overlay retains pointer and replies `XdndStatus(accept=false, None)`. |
| **Releasing mouse button outside wheel while wheel is visible** | **Drops into whatever Nemo folder/desktop is underneath!** If `Shift` is still held, Nemo executes a **native `MOVE`**! | **Safely cancels the drag** (icon snaps back; zero files moved or copied). |
| **How to resume a normal Nemo drag after summoning wheel** | Move pointer outside the wheel cluster (and remember to release `Shift` if you want `Copy` instead of `Move`). | Press `Shift` a second time (toggle-off) to dismiss the wheel and continue dragging in Nemo. |
| **X11 Server Work on Child Wheel Open/Close** | Requires `CreatePixmap(depth=1)` + `PolyFillRectangle` + `ShapeMask(SO::SET, SK::INPUT)` on each topology change (`~150 µs`). | Zero `ShapeMask` updates during session; only `clear_input_shape_to_empty` on unmap. |

---

## 3. Verdict & Architectural Impact

- **Verdict:** **PASS** — Both `ShapeInput` pass-through (including dynamic child-wheel expansion) and Capture-All work cleanly on Cinnamon/Muffin X11.
- Both modes must be supported via `input.passthrough` (`bool`) in `config.toml`, with the `Shift`-held native `MOVE` hazard of `passthrough = true` explicitly documented in `ADR-016` and `PLATFORM_INTEGRATION.md`.
