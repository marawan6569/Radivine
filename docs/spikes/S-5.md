## 1. Objective & Hypothesis

Verify **H-5** on the live Linux Mint 22.3 Cinnamon desktop:
1. Identify the active X11 compositor (`_NET_WM_CM_S0`), window manager (`_NET_SUPPORTING_WM_CHECK`), X11 extensions, RandR monitor geometry, and 32-bit ARGB `TrueColor` visual.
2. Compare `_NET_WM_WINDOW_TYPE` atoms (`DND`, `POPUP_MENU`, `NOTIFICATION`, `UTILITY`) on an `override_redirect = true` 32-bit ARGB window with `_NET_WM_BYPASS_COMPOSITOR = 2`: verify zero Muffin map/unmap animations, zero unwanted rectangular drop shadows, zero input focus theft, and zero taskbar/client-list entries.
3. Verify premultiplied BGRA pixel byte order (`[B, G, R, A]` on little-endian x86_64) via `shm::PutImage` + `GetImage` readback.
4. Benchmark `tiny-skia` RGBA → X11 BGRA swizzle + `shm::PutImage(..., send_event=true)` + `ShmCompletion` across full-screen (`3840×1080`), multi-wheel cluster (`800×600`), and single-wheel (`300×300`) damage rectangles.

> [!IMPORTANT]
> **Critical Architectural Finding:** Uploading the full `3840×1080` (`16.59 MB`) framebuffer on each frame stalls the NVIDIA Xorg driver for **32.6 ms at p95** (`< 30 fps`), whereas uploading only the active wheel cluster's damage bounding box (`300×300` to `800×600`) completes in **48 µs – 953 µs at p95** (`> 1,000 fps`). Therefore, **damage-rectangle clipped swizzling and `shm::PutImage(src_x, src_y, dst_x, dst_y, dst_w, dst_h)`** (or sizing the overlay window to the active monitor / cluster bounding box) is a **hard requirement** for `radivine-x11`.

## 3. Verdict & Architectural Impact

- **Verdict:** **PASS** (`_NET_WM_WINDOW_TYPE_DND` + `_NET_WM_BYPASS_COMPOSITOR = 2` maps in `169 µs` with zero Muffin animations or focus changes; damage-rect MIT-SHM `PutImage` completes in `48 µs` for a single wheel and `953 µs` p95 for an `800×600` cluster).
