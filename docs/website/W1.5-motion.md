# W1.5 — Radial motion and visual direction

Authorized scope: the existing homepage and reusable motion components, 2026-10-27. This extends the W0 visual contract's static three-step composition and short-transition limits. W0's product evidence, protected assets, release links, compatibility caveats, and media provenance requirements remain in force. W2 content infrastructure, W3 simulation, release workflows, and deployment are outside this phase.

## Composition

The visual idea is a point becoming a direction. A large typographic hero balances a radial construction drawing. Eight annular sectors surround the unchanged vine symbol; a second, smaller wheel branches away through an open bridge facing the parent. Geometry is informed by the wheel's polar sectors and neutral bridge, but counts, dimensions, timing, and annotations are editorial. It is not a screenshot, accurate layout export, or functioning wheel.

Green ink and pale mint define Light; forest surfaces and mint accents define Dark. A restrained lime sector marks a new direction in both palettes. The original symbol rests on a pale circular mount in either theme, preserving its green colors without filtering, recoloring, or editing an original asset. All new graphics are native SVG/CSS components in the website.

The workflow uses the same geometry to connect four moments: files, invocation, submenu, action. A sticky illustration accompanies a numbered vertical sequence on larger screens. On touch-sized or short viewports, the composition becomes a complete diagram followed by compact steps. Feature scenes alternate text and illustration, then resolve into a wide configuration panel. Paper layers, format branches, and slider geometry express existing features without mimicking native windows or exposing pretend controls.

## Motion vocabulary

| Primitive | Behavior | Timing |
|---|---|---|
| Headline reveal | Masked lines unfold with a small rotation; headline stays real HTML | 700 ms, 80/180 ms offsets |
| Supporting entrance | Brand, release, description, actions settle horizontally | 700 ms; up to 440 ms offset |
| Radial assembly | Root sectors assemble about their common center, then a child wheel opens | 1100 ms; 45 ms sector stagger; child 1000 ms |
| Path drawing | Normalized SVG strokes trace a connection or highlight | 1100 ms |
| Layer assembly | File sheets, format chips, and slider handles arrive in sequence | 900 ms; 90 ms stagger |
| Pointer response | Hero art translates at most ±8 px horizontally and ±6 px vertically | 700 ms easing; fine mouse pointer only |
| Scroll story | Nearest step changes the illustration; continuous scroll fills a progress line | 700 ms transition; no scroll interception |
| Hover | Feature artwork lifts 5 px / rotates 1°; CTA arrow moves 2 px | 700 ms / 180 ms |
| Theme | Text, canvas, buttons switch atomically; decorative radial fills/strokes recolor | 180 ms, decoration only |

Shared easing: `--ease-out: cubic-bezier(0.22, 1, 0.36, 1)` and `--ease-smooth: cubic-bezier(0.65, 0, 0.35, 1)`. Shared tokens and keyframes live in `src/styles/motion.css`. `RadialArt.astro` owns the reusable polar illustration; `motion.ts` owns viewport enhancement and cleanup. Components keep their own state-specific CSS.

## Enhancement and accessibility contract

- All headings, descriptions, links, and four workflow steps exist in static HTML. No text waits for IntersectionObserver or a scroll trigger to become visible.
- Illustrations are `aria-hidden`, with visible captions stating their illustrative status. Changes do not generate screen-reader announcements or add focus stops.
- Ordinary page scrolling is preserved. There is no scroll hijacking, pinned viewport lock, drag capture, fake command execution, or keyboard simulator.
- Desktop story enhancement requires at least 52 rem width and 38 rem height. Pointer response additionally requires hover and a fine pointer. Mobile retains finite hero and feature motion, with an unpinned complete workflow diagram.
- Reduced motion disables all animations/transitions, smooth scrolling, pointer tracking, and story state updates. The desktop story becomes compact and unpinned. A live preference change removes listeners, queued frames, custom properties, and active states; restoring the preference reinitializes safely.
- Missing JavaScript leaves the complete illustration and readable workflow. Native mobile disclosure, system theme CSS, and existing external links remain usable.
- No permanent animation loop. IntersectionObserver starts one-time visual reveals; scroll work is attached only while the story intersects the viewport; a single requestAnimationFrame coalesces events. Cleanup handles media changes and browser back/forward restoration.
- Theme initialization, persistence, System handling, and cross-tab behavior remain W1's. Text-bearing surfaces do not crossfade through low-contrast intermediate palettes.

## Deliberate limits

No current native-application media was approved for this phase. Historical screenshots remain unused. Every feature illustration is explicitly labeled, and the guide remains the destination for real usage. The browser practice area remains future W3 work. No runtime animation library is needed for this finite choreography; the complete home JavaScript remains approximately 4 KB raw, including the original theme/navigation logic.
